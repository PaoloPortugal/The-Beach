# C06 + C07: permission modes and plan approval, built

Features: C06, C07, S02

The decisions and the spike that settled how Claude Code behaves are in
[2026-10-02-c06-c07-spike](2026-10-02-c06-c07-spike.md). This entry is
the build on branch `c06-c07-modes-plans`.

## Decided while building (user's, 2026-10-03)

- **Protocol approved by the user:** two capabilities, `permission_modes`
  and `plans`, so other tools with approval modes or plan modes can
  declare them; "Allow and switch to auto mode" only on Bash prompts and
  only once the session has been seen in auto. The aim, in the user's
  words for the whole feature: behave nigh equal to the terminal.
- **No launch picker** (a correction of an earlier note, see the spike
  entry): sessions start in Claude Code's own mode.

## Picked by me, for review

- **Message `kind: "plan"`.** The user decided the plan shows as its own
  full-width Markdown message. To carry that, a chat message can have
  `kind: "plan"` (`message.started` and the history). The alternative was
  drawing the plan from `plan.asked` alone, but then it would vanish when
  the plan resolved and wouldn't be in a resumed conversation.
- **The card's words:** "The orchestrator has a plan for you to
  approve:" and "Would you like to proceed? The plan is above, in the
  chat."; the header's "Mode: Auto". The choice buttons use Claude Code's
  own words.
- **Plans in resumed history** (cba4956): `store.ts readHistory` emits a
  `<tool_use_id>:plan` message for each ExitPlanMode call, like live, so
  a resumed conversation shows its plans. Not asked for; added because
  otherwise the record the user wanted would only last while the
  sidecar ran.
- **Our mode names** (`PermissionModes`, `chat/permission_modes.gd`):
  Manual, Accept edits, Plan, Auto; an unknown id shows as is.

## What changed

- **Protocol** (additive): capabilities `permission_modes` and `plans`;
  session `mode` and `session.updated` with `mode`; a permission's
  optional `modes` and `permission.respond`'s optional `mode` (allow
  only, one of them); `plan.asked`, `plan.resolved`, `plan.answer`;
  snapshot `plans`; agent waiting reason `plan`; message `kind`.
- **Sidecar** (Claude provider): the mode from the orchestrator's hooks
  (`noteMode`); `PermissionRequest` registered for
  `AskUserQuestion|ExitPlanMode|Bash`. ExitPlanMode is held like a
  question: approving echoes the plan's input back with a session-only
  `setMode`; sending back denies with the note (or a default line) and
  closes the call as denied, since Claude Code sends no hook for it
  (spike finding 3). Answered in the terminal, the plan resolves from
  `PostToolUse`, a transcript refusal or the turn ending, and the hook is
  released then (finding 4). Bash prompts in Manual or Accept edits are
  held only so an allow can switch to auto (finding 6); every other
  answer still goes through the relay, and the hook is let go when the
  call ends (finding 7). A stop declines held plans.
- **Godot:** `SessionStore` keeps `mode`, `plans` (queued with
  permissions and questions as kind `plan`, by `asked_at`) and message
  `kind`, with a `plans_changed` signal; a snapshot resync reports the
  mode as changed. The chat panel's header shows the mode; plan messages
  are drawn full width with a border and a "Plan" caption; the status
  line says a plan waits. The C05 card gained the plan's choices
  (`approve_plan(mode)`, `keep_planning()`, the note and Send as with
  Deny) and "Allow and switch to auto mode" for permissions with
  `modes`. No answer button takes keyboard focus.
- **Fake provider:** `mode` (Shift+Tab's cycle), `plan` (plan mode, a
  plan; a note brings a revised one), and `permission` offering the
  switch in Manual or Accept edits. Sessions start in auto.
- **try-claude:** `/switch`, `/approve`, `/keep`.

## Tested

Sidecar: `modes-plans.test.ts` (modes from hooks, both plan answers from
the world and the terminal, the held Bash hook and its refusals),
`store.test.ts` (plans in history), `dev-fake.test.ts`; 189 pass.
Godot: `session_store_test.gd`, and `world_test.gd`'s modes and plans
part, by hand through a recording stand-in for the sidecar and live
through the fake; every suite passes with and without the fake.

Left for the live check with a real `claude`: "No, keep planning"
answered in the terminal (expected: the transcript's refusal resolves
the plan, by external), whether Claude Code's terminal offers the auto
switch on Bash prompts in plan mode or on PowerShell prompts (we offer it
only on Bash, in Manual or Accept edits), and the header following a
Shift+Tab switch.

## Live check (2026-10-03, the user, `claude` 2.1.288)

Passed: every fake step, and with the real `claude` every step of the
checklist, including the three above: "No, keep planning" in the
terminal took the card away; the header followed Shift+Tab once a
message was sent; the command prompt (`cat > README.md <<'EOF' …`) was
Bash (checked in the transcript), and the card offered the switch to
auto. A PowerShell prompt wasn't seen.

The user noticed the terminal sometimes offers "Yes, and always allow
access to <folder>", which the world doesn't. Raised with the user as a
design question (C05 decided "Don't ask again" isn't offered).
