# C04: the tool-call log

Features: C04, S02

## The questions

C04 was only "some form of log of the tool calls, visible from the chat
panel". Gone through with the user (2026-10-02):

- **Order of work:** C04 first, then C06 and C07 together on one branch.
- **Shape: inline and collapsed.** After each chat message, the calls
  that followed it fold into one line ("▸ 5 tool calls"); a click opens
  each call's summary, status, result line and input. Not one line per
  call in the chat, and not a separate tab.
- **History: from the transcript too.** Calls from before the world was
  watching (a resumed conversation, a reconnect) show like live ones.
- **Subagents: nested.** A subagent's calls show inside the Agent call
  that started it, expandable, not mixed into the orchestrator's.
- **Scope: core.** `tool.started` / `tool.finished` were already generic.

## What changed

- **Protocol** (additive, no version change): `tool.started` gets an
  optional `within` (the call that started the subagent making this
  call). `session.get_history` answers `{messages, tools}`; a
  `history_tool` is a call with `status` (running, ok, error, denied),
  `result`, `after` (the message it came after, or null) and `within`.
- **Sidecar:** a generic `HistoryLog` (`src/history.ts`) keeps what the
  world saw, messages and calls, for any provider; the Claude provider
  and the fake use it. Live `within` comes from the same pairing that
  names a subagent's parent (the oldest open Agent call of its type).
  From a transcript (`readHistory`), the main conversation's calls are
  read in order (a `tool_use` starts one, its `tool_result` ends it),
  then each subagent's from `subagents/agent-<id>.jsonl`, tied to its
  Agent call exactly by `toolUseId` in the `.meta.json` beside it.
  `toolDenialKind` on a result (undocumented; seen `user-rejected`,
  `permission-rule`, `automode-blocked`, `automode-unavailable`) marks a
  refusal rather than a failure. A call with no result shows as failed,
  "No result was recorded." (Claude Code closed mid-call).
- **Size:** inputs can be up to 64 KiB each and the history keeps 5000
  calls, which could push one answer past the 32 MiB Godot accepts. So
  one answer carries at most 8 MiB of inputs; past that the oldest calls
  come without theirs (`fitInputs`).
- **Godot store:** each call gets `after` (the latest message) on
  `tool.started`; the history's calls go before the live ones, and a
  known call takes the history's copy (the reply follows every earlier
  event, and it knows `after` for calls seen before the chat loaded). A
  conversation switch replaces calls like messages. `tool_tree` lays the
  log out in one pass. 5000 calls kept (was 500).
- **Chat panel:** `ToolFold` under every message row (a row is now the
  bubble plus its fold), and one at the top for calls before the first
  message, shown only while every message is. Tool text goes in plain
  Labels only, never BBCode. Status as words and colour: the font has
  no ✓/✗ (it has no ▸ either; that one comes from the system's fallback
  font, as in the sessions menu).

## A bug on the way

The fake provider's new `tools` trigger never fired: the script that
added it wrote `\b` in a Python string, which became a backspace
character in the TypeScript regex. The Godot live test caught it (the
fake echoed instead). Fixed, and `dev-fake.test.ts` now plays the tools
turn so it can't silently break again.

## Tests

- Sidecar: live history with calls (`after`, `within`, failure result),
  transcript reading (`store.test.ts`), the input budget, the fake's
  tools turn. 169 checks pass, typecheck clean.
- Godot store: by hand (placement, history merging, the tree, a
  `within` naming an unknown call, a switch) and live with the fake
  (every live call placed exactly as the sidecar's history has it).
- World test: fold line and counts, statuses, nesting, live growth,
  Details, `[b]` shown as written, history's calls arriving; live with
  the fake, Agent calls each holding their subagent's three calls and a
  tools turn with one failure. All headless suites pass.

Not checked yet: the look, and a real `claude` session's calls (needs a
live check with the user).
