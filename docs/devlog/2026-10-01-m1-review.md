# M1 review

Features: C02, S01, S02, C05

An overall review of `m1-world` against `main` before merging M1: the
sidecar changes (following `/clear`, a moved conversation, agent view
off), the Godot side (store, chat, card, islands, agents, post, player),
tests (145 `node:test`, typecheck, the three Godot tests with and
without the fake) and the docs. Nothing blocking.

## Fixed

- **History fetched once.** The chat controller asked for
  `session.get_history` once per session; if that failed, the chat stayed
  empty until a restart. Opening the chat now asks again.
- **Replies lost with a dropped connection.** On a reconnect the client
  kept the old commands' callbacks, which no reply would ever reach. The
  C05 card would have stayed disabled for that request ("sending"
  forever), and the history fetch would never retry. The client now
  answers each with an `error`, code `disconnected` (Godot's own: the
  command may or may not have arrived). Tested in `sidecar_client_test`
  (a command sent just before closing the socket) and `world_test`.

## Left as is or for later (user's decisions)

- The protocol still accepts a note with `allow`; the world no longer
  sends one. Left as an unused feature.
- Export presets, when made, leave out `tests/` and the checklist overlay.
- All UI is a placeholder; it only has to work for now.
- The bubble re-wraps the whole reply on each streamed batch: fine at
  today's lengths.

## /resume in the terminal

Live check (user, `claude` 2.1.285): `/resume` inside a world session's
terminal was followed like `/clear`, and world chat reached the resumed
conversation, but the notice said "/clear ... Claude no longer
remembers". The game's log (`user://logs/godot.log`, which has the
sidecar's lines) showed the switch. Two islands naming one conversation
(one session resuming the other's) turned out harmless: each island's
chat goes to its own terminal.

SessionStart would say `resume` vs `clear`, but it can't be an HTTP
hook. So the sidecar reads the new conversation's transcript: chat in it
means a resume (the prompt that woke it is dropped; it arrives live).
The user chose a notice plus the resumed chat in the world: the
session's history becomes that chat (`conversation_resumed`), Godot
reloads the history on every `native_id` change and replaces its chat
(after `/clear` the sidecar keeps the old chat, so it stays), and only
the latest switch notice shows. Tests: `conversations.test.ts` (resume
and clear histories), `session_store_test` (replace keeps what came
after the switch), `world_test` (notice and the panel laid out again).

Re-check (user): `/resume` now showed the resumed chat, but `/clear` was
taken for a resume. Claude Code writes the `/clear` command itself into
the new transcript as a user entry, which `readHistory` counted as chat.
Both switches also only reached the world at the next message. Rather
than patch the guess, the user chose the documented `SessionStart` hook:
it says `clear` or `resume` with the new id, at once. It can't be an
HTTP hook, so it will be a command hook in exec form (no shell) running
the sidecar executable as a relay. Handed off to a new session; see
NOTES → S02 → Following the conversation.

## SessionStart through a relay

Built as decided. `SessionStart` allows only command (and MCP tool)
hooks, so it runs the sidecar executable in a new `relay` mode, in exec
form (`command` plus `args`, which Claude Code spawns directly, with no
shell). The relay reads the hook's JSON from stdin and posts it to the
hook endpoint. The URL and token come from a relay file in the session's
private run folder, the same pattern as the launcher's session file, so
the token is never on a command line. The relay always exits 0 within
2 s and prints nothing. That matters because a SessionStart hook's stdout
becomes Claude's context. Matcher `^(clear|resume)$`, timeout 5 s (the
in-session `/resume` waits for it).

The session switches on `source` clear/resume with a new id, at once.
The old first-hook switch stays as a fallback, now classed by whether the
transcript holds an assistant entry. `readHistory` skips local-command
entries (`<command-name>`, `<local-command-stdout>`,
`<local-command-caveat>`), which also cleans S04 resume histories and
titles.

`claude -p --resume` probes (2.1.285) settled what the docs left open.
Claude Code runs an exec-form hook from an absolute path with spaces
(`C:\Program Files\nodejs\node.exe`, and the packaged `sidecar.exe`). It
skips the hook for `startup`. Claude saw no added context. Tests: relay
argv with a shell-hostile folder name, spawned without a shell, and every
failure (no server, wrong token, hanging server, open stdin, bad file)
exits 0 with an empty stdout.

Live check with the user (2026-10-01): `/clear` and `/resume` both
showed their notice at once, before any message, and the resumed chat
showed without command lines. The user then asked for `/clear` to clear
the world's chat window too, instead of keeping the old chat (their
earlier decision). The session's history now starts empty on `/clear`,
so Godot's reload on the `native_id` change clears the panel and bubble.
The notice now says the earlier conversation can be brought back with
`/resume`, replacing "Claude no longer remembers the chat above", since
nothing is above it any more.

Re-check (user): `/clear` emptied the window and bubble at once, with
the new notice, and the next chat showed alone. The user noted that
attaching to outside sessions (planned) must follow `/clear` and
`/resume` too; recorded under NOTES → Open questions 5.
