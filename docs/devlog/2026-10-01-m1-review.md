# M1 review

Features: C02, S01, S02, C05

An overall review of `m1-world` against `main` before merging M1: the
sidecar changes (following `/clear`, a moved conversation, agent view
off), the Godot side (store, chat, card, islands, agents, post, player),
tests (145 `node:test`, typecheck, the three Godot tests with and
without the fake) and the docs. Nothing blocking.

## Fixed

- **History fetched once.** The chat controller asked for
  `session.get_history` once per session; if that failed, the chat stayed
  empty until a restart. Opening the chat now asks again.
- **Replies lost with a dropped connection.** On a reconnect the client
  kept the old commands' callbacks, which no reply would ever reach. The
  C05 card would have stayed disabled for that request ("sending"
  forever), and the history fetch would never retry. The client now
  answers each with an `error`, code `disconnected` (Godot's own: the
  command may or may not have arrived). Tested in `sidecar_client_test`
  (a command sent just before closing the socket) and `world_test`.

## Left as is or for later (user's decisions)

- The protocol still accepts a note with `allow`; the world no longer
  sends one. Left as an unused feature.
- Export presets, when made, leave out `tests/` and the checklist overlay.
- All UI is a placeholder; it only has to work for now.
- The bubble re-wraps the whole reply on each streamed batch: fine at
  today's lengths.

## /resume in the terminal

Live check (user, `claude` 2.1.285): `/resume` inside a world session's
terminal was followed like `/clear`, and world chat reached the resumed
conversation, but the notice said "/clear ... Claude no longer
remembers". The game's log (`user://logs/godot.log`, which has the
sidecar's lines) showed the switch. Two islands naming one conversation
(one session resuming the other's) turned out harmless: each island's
chat goes to its own terminal.

SessionStart would say `resume` vs `clear`, but it can't be an HTTP
hook. So the sidecar reads the new conversation's transcript: chat in it
means a resume (the prompt that woke it is dropped; it arrives live).
The user chose a notice plus the resumed chat in the world: the
session's history becomes that chat (`conversation_resumed`), Godot
reloads the history on every `native_id` change and replaces its chat
(after `/clear` the sidecar keeps the old chat, so it stays), and only
the latest switch notice shows. Tests: `conversations.test.ts` (resume
and clear histories), `session_store_test` (replace keeps what came
after the switch), `world_test` (notice and the panel laid out again).
