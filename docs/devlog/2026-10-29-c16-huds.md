# C16: the drawn HUDs

Features: C16, C08, C11, C15, A05, W04, W06, W07

Step 3 of C16's migration order (NOTES → C16): the text drawn with
`draw_string` and the HUD's corner labels, in the game's language. No
real language ships yet, so in English nothing looks different.

## Decided (user's, 2026-10-29)

1. **D01's text stays on its own branch** (step 5), though D01 is now
   merged and its HUD is a drawn one. I recommended this: it follows the
   decided migration order, and the catch card's new wording (no
   article picked in code) gets its own review. This branch only
   leaves the fishing HUD as it is.

## My picks (said so in NOTES)

- Hints translated under the context "hint", the hotbar's names under
  "hotbar".
- The limits' time and date as translatable layouts under "time":
  "{hour12}:{minute} {am_pm}" (a language may use `{hour24}` instead),
  "{weekday} {time}", "{month} {day}", with the short names under
  "weekday, short" and "month, short", since "Sun" and "May" are
  ambiguous alone.
- Each drawing HUD keeps `drawn`, the text it last painted, so the
  world test checks what is really on screen rather than a getter
  that could drift from the painting.
- W04's arrow label goes from content to translated: it holds our "m"
  as well as the project's name.

## Found on the way

- `tests/locale/pot.gd`'s doc said a lone placeholder ("{reason}") is
  never taken. The code counts a placeholder's name as letters, so it
  is taken. I first changed the code to match the doc, which dropped
  step 2's "{percent} %" and "{degrees}°" from the template, entries
  meant for a language to space or reorder. I reverted the code
  and fixed the doc (and NOTES) instead. The extractor test now checks
  "{month} {day}" is taken.
- A test session made by `session.snapshot` is "taken back", so W04
  has no arrow for it; `_huds` uses `session.created`.

## Not done

- The chat header's usage line and turn hints (`UsageText.header`,
  `turn`) are the chat's chrome: step 4.
- The key's name in the crosshair's hint is the keyboard's own
  (`OS.get_keycode_string`), English on most systems, as before.

## Review

- Security review: no rule broken. It asked for a test with content
  that holds placeholders, so a later `String.format` or second `fill`
  can't slip through. `_huds` now has a project named "Back {n}" and a
  limit named "{when} {percent}", both shown as written.
- Security review and docs-sync both found that the big map's title
  was still a fixed `"%s · %s"`, while NOTES said "{title} · {state}".
  The code now matches NOTES (a translatable layout).
- Docs-sync: the hotbar's slot numbers aren't run through
  `Languages.number`, because they name the 1 to 9 keys. NOTES now
  says so.
