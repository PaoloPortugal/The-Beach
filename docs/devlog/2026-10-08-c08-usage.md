# C08 token usage, built

Features: C08, S02 (NOTES → C08 Token usage; research and spike:
2026-10-03-c08-usage-spike)

Built on branch `c08-usage` over 2026-10-03 to 2026-10-08, after the
design and the shell-string exception were decided in the spike.

## Sidecar

- **Protocol:** the `usage` capability, `usage.updated { usage }` (the
  whole figures each time), the snapshot's `usage` (null until the first
  count) and history user messages' `turn_tokens`. The registry drops a
  `usage.updated` that changes nothing; the history log puts the turn's
  tokens on the user message that started it.
- **Counting** (`providers/claude/usage.ts`): each API call once by its
  message id, subagents left out, context as the latest call's input
  plus cache reads and writes, a turn's output tokens from one user
  message to the next. A resumed conversation is counted from its
  transcript with its history; `/clear` starts over, keeping the
  limits.
- **The status line relay:** `statusline <file>` mode (the hook relay,
  posting to `/status`, printing nothing, always exiting 0);
  `providers/claude/statusline.ts` keeps the user's own status line
  (their settings, or the project's) and sets none then;
  `launch/shell-command.ts` builds the one command string.

## Windows short names that can't be guessed

The first command string guessed 8.3 names (`PROGRA~1`) and checked each
guess was the same file. Testing with hostile folder names showed
Windows **hashes** some short names instead: `a b` became `AB2761~1`,
and so did mixed-case temp folders, so guessing failed and those
sessions would have had no status line. Now, when no guess fits, the
sidecar asks Windows for that one folder's short name: `powershell.exe`
with a fixed script (`Scripting.FileSystemObject` → `ShortPath`), the
path in the environment variable `SIDECAR_SHORT_PATH`, never on a
command line, once per folder per run. The answer is trusted only if it
is the same file (volume and file index), on the same drive, with every
component safe.

`sidecar/test/usage.test.ts` runs the real command string in Git Bash,
Windows PowerShell and PowerShell 7 (`sh` elsewhere) from folders named
with spaces, `;`, `&`, `$( )`, backticks, quotes and accents, and checks
the recorder gets exactly its 3 arguments and nothing else runs. A name
whose short name is still unsafe (`$(NEW-~1`) gives no command.

## Checked again: no exec form (2026-10-08)

Claude Code 2.1.294's raw statusline and settings docs still run a
status line only through a shell, with no `args`. New in the docs:
`rate_limits.spend_limit` (dollars, for gateways; ignored, no cost
wanted) and "Claude Code drops a window once its resets_at passes".
The sidecar keeps the last limits when `rate_limits` is absent, so the
world hides a limit whose `resets_at` has passed.

## Godot

Asked and decided (user's, 2026-10-08), all as recommended:
- The plan's limits in the **bottom-right corner, always shown**, the
  chat and the maps included (the minimap is top left, the waiting count
  top right).
- The limits read **"5-hour 74% · resets 3:40 PM"**: percent and reset
  time, like the terminal's `/usage`.
- The header's totals as **in / out** ("↑ 2.1M in · ↓ 48k out"), not one
  sum: cache reads repeat the history on every call, so a sum of
  everything is mostly cache reads. The exact four on hover.
- Each turn's hint is a **dim line under the turn** ("↓ 1.2k tokens"),
  at the end of the chat while working.

My picks, conventional: compact numbers like the terminal's (950, 1.2k,
34k, 1.1M, 12M); a reset today as a time, within a week as a weekday
and time, else a date; nothing in the header until something is counted
(with transcripts off, the context % alone).

The store keeps `usage` and each turn's tokens on its user message. The
corner picks, per limit, the latest window across sessions (latest
`resets_at`, then the highest use), since each session's figures stay as
they were until it hears again.

## Bugs found on the way

- The fake's heavy turn sent fractional cache tokens; the sidecar's
  schema check dropped those events (as it should), and only the Godot
  live test noticed, through the history and the store disagreeing.
  The fake rounds now, and `dev-fake.test.ts` fails on any event the
  sidecar drops.
- A turn with no tokens has 0 in the store (it saw the message start)
  and none in the history (the message wasn't complete yet). Both mean
  no hint; the tests compare turns that have tokens.
- GDScript lambdas capture locals by value: the corner's test clock had
  to be a new lambda per time, not a changed variable.

## Review fixes

- **CI, Linux only:** the POSIX shell test expected a command for a
  folder named `a<tab>b`, but control characters are refused by design
  (fish and friends). The test was wrong; it now expects no command.
- **Security review, should-fix:** the short-name lookup ran
  `powershell.exe` by bare name, which Windows may look for in the
  working folder first (the sidecar inherits Godot's), with the full
  environment. Now Windows PowerShell by its full path under
  `SystemRoot` (none there: no answer, so no status line for that
  session), from the temp folder, with the user's environment cleaned
  like any launched program's (Security rules → Clean child
  environments). A first try with only `SystemRoot` and the path
  answered in under a second here but hung on CI's Windows runner (each
  lookup ran into its 10 s timeout, so no command at all), so it went
  back to the full, cleaned environment, which had passed CI before. A new test asks the real Windows about
  folders named `$(New-Item PWNED)`, `` `ni PWNED` `` and
  `a';ni PWNED;'b`: nothing runs, each answer is that very folder, and
  the program is always the System32 one. All three do get short names
  back (`$(NEW-~1`, `` `NIPWN~1 ``, `A'_NIP~1`), so the identity check
  is exercised, and none is safe for the command string anyway.
- **Security review, notes:** the lookup blocks the sidecar (under a
  second here, at most 10 s, once per folder per run); a delayed hook
  times out to the terminal's own prompts, so it fails safe; written
  down in NOTES. The user's own status line is checked only when a
  session starts or resumes: documented as a limitation.
- **Limits per provider** (user's requirement, 2026-10-08): a user may
  run Claude, Codex and OpenCode sessions at once, each with its own
  plan. `SessionStore.usage_limits` now groups by each session's
  `provider`, and the corner shows a line per provider, named (from the
  hello's `providers`, else the id) only when more than one has limits,
  so Claude alone looks as before. More lines grow upwards from the
  corner. The protocol's `limits` still only had `five_hour` and
  `seven_day`: a general shape for other tools' limits was the user's
  call (asked at hand-over; decided below).

## `usage.limits` becomes a list (user's decision, 2026-10-08)

Asked at hand-over: keep `limits` an object with only `five_hour` and
`seven_day`, or make it general now. Decided as recommended: a list,
`[{id, label, used_percent, resets_at}]`, in the provider's order,
empty when none are known.

- **Why:** other tools (Codex, OpenCode, ...) have limits of their own,
  with other windows and names (a daily one, a monthly one). With a
  stable `id` per provider and the provider's own `label`, those fit
  without another protocol change, and Godot needs no list of known
  limits: it shows each by its label, in the order sent.
- **The label is untrusted text** (Security rules → session content): a
  provider's words, shown in a plain `Label` (never BBCode), at most 40
  characters (the schema's limit, so a long one can't push the corner
  across the screen), with no control characters or bidi overrides (so
  a label can't add a fake line to the corner or turn another
  provider's text around; security review). `id` is a machine name (`^[a-z][a-z0-9_]*$`).
- **Sidecar:** `statusFiguresIn` maps `rate_limits.five_hour` and
  `seven_day` to `five_hour` "5-hour" and `seven_day` "Weekly". The
  counter now keeps the last known limit per id: before, an input with
  `rate_limits` replaced them all, so one where Claude Code had dropped
  a window that was over lost it at once; now it stays, and Godot hides
  it as over (the same as an input with no `rate_limits`). The registry
  drops a `usage.updated` whose list gives an id twice (the schema can't
  say "unique by id").
- **Godot:** `SessionStore.usage_limits(now)` returns `{provider:
  [limits]}`, the same merge rule per provider and id (latest
  `resets_at`, then the highest use; a window that's over left out). A
  limit one session has and another doesn't goes in after that
  session's previous one, so the provider's order holds across
  sessions. Nothing visible changes for Claude: the corner reads as
  before.
- **Tests:** the schema test takes the list and refuses the old object,
  an empty or 41-character label, one with a new line, a bidi override
  or a NUL, an id that isn't a machine name and a
  limit without its label; the counter keeps a dropped window; the
  registry drops a repeated id; the store's merge and order across
  sessions and providers with other ids; the corner shows another
  provider's labels as plain text, in its order; the live checks (store
  and world, with the fake) read the list.
