# W05: clusters of islands by repository

Features: W05, S03, W07

The second feature of the "many sessions" milestone. Built on branch
`w05-clusters`.

## Renamed

The user renamed archipelagos to **clusters** (2026-10-02): in the docs,
the UI and the code.

## Decisions (the user's)

The direction from 2026-09-30 was "both": clusters chosen when creating
a session, and automatic grouping by repository. The details:

- **Same repository** = the same git repository, worktrees included
  (e.g. a repo and its `.claude/worktrees/*`). A folder outside git is
  its own cluster.
- **Automatic first, override in the menu.** A session joins its
  repository's cluster on its own; the first one of a repository makes a
  new cluster named after the repository's folder. The sessions menu has
  a cluster selector to pick another running cluster or "New cluster"
  instead. I offered a selector row in the menu or an extra step after
  choosing the folder; the user chose the row.
- **Not remembered.** A cluster lasts while it has sessions; when its
  last one ends, it and its spot are freed.
- **Layout until bridges (W06):** each cluster takes a spot on rings
  around the spawn platform, its islands close together around it.
- **The sidecar works out the repository** and sends it in the protocol,
  rather than the game reading `.git` itself.
- **Shown by name only:** named after the repo folder (a manual new
  cluster after the session's folder), the Running list grouped under
  cluster headings, nothing in the world yet (a sign comes with props).
  Placeholder UI, like all UI.

## How it's built

*Sidecar.* `repo.ts` finds the repository from the `.git` files alone,
no git command: walk up to the first `.git`; a folder is the repository;
a file's `gitdir:` leads to the worktree's git folder, whose `commondir`
leads to the main `.git`. A submodule's git folder has no `commondir`, so
it counts as its own repository. The registry adds `project.repo` when a
session is announced. Additive and optional, so still protocol version
1; a `repo` in a command is dropped.

*Godot.* `SessionClusters` (a `RefCounted` owned by `SessionIslands`)
keeps the clusters and places the islands; the old ring-per-island
layout is gone. The launcher records the menu's choice against the
session id from the command's reply, which always comes before
`session.created`, so the choice is there when the island is placed.
`session_at` now picks the nearest island, since a cluster's islands
can be close enough for two to match.

My picks, said to the user: cluster spots 360 m apart (six per ring, as
before), islands 100 m apart (land reaches about 40 m from an island's
centre), the first island in the middle and then rings of 6, 12, 18;
names repeated get a number ("game 2"); the selector resets to Automatic
each time the menu opens; search matches cluster names too.

## Limits

- A cluster of more than 7 islands reaches 200 m out and can come close
  to a neighbour's. Fine until bridges and a real layout (W06).
- Nothing in the world names a cluster yet.

## Live check

Passed with the user and the real `claude` (2026-10-02), with two
sandboxes: a git repository with a worktree in `.claude/worktrees/side`,
and a folder outside git. The repository and its worktree shared one
cluster, close together; the other folder got its own cluster far away;
"New cluster" made "notes-app 2", and choosing the repository's cluster
put a notes-app session there; the Running list was grouped, search by
cluster name worked, and the selector was back to Automatic on opening;
ending a cluster's last session removed it from the list and the
selector, and a new cluster took a free spot.

After the check the user asked that a session moved to another cluster
by hand not take its repository's later sessions along (they followed
it to the first cluster holding one). Now each cluster remembers the
repository it was made for automatically, and only that one is joined
automatically.

The first start failed with parse errors and the sidecar missing `ws`:
the game had been started from a fresh Claude worktree that was never
imported and had no `npm ci`. Nothing to fix in the code; a fresh
worktree needs both before the game runs from it.
