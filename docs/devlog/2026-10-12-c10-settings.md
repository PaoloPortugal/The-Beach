# C10: the settings menu

Features: C10, A05, W03, W04, W09, C01, S03

The user asked for a settings menu with graphics settings after W11
(2026-10-08). Designed 2026-10-12 as choices with a recommendation each;
the user took all four and gave no reasons beyond the choice: Esc opens
it; a focused first set (graphics, mouse sensitivity and field of view,
the chime, being taken to a new island; rebinding later); tabs; changes
applied at once and saved, with Reset to defaults. NOTES.md → C10 has
the decisions and the rejected options.

## What was built, and my picks

- `Settings` (values and their file) and `SettingsMenu` (the panel),
  under `world/settings/`; `world.gd` → `apply_settings` applies them.
- Ranges and defaults: render scale 50-100 %, mouse 0.25-3x, field of
  view 60-110°, FPS caps Off/30/60/120/144/240, shadows High (as built:
  4 splits, 4096 atlas) / Low (2 splits, 2048) / Off.
- Esc: the other UIs already took Esc in `_input`, so the menu opens in
  `_unhandled_input` and only sees an Esc nobody else used. The player's
  own Esc (free the mouse) is gone: opening the menu frees it.
- The chime's toggle moved out of the sessions menu, keeping its own
  `[attention] sound` key in the same file.
- Under Compatibility, sun shadows stay off whatever the setting (Watch
  items); the menu shows Off, greyed out, rather than the saved value.
- The tabs are sized to the tallest so the panel doesn't jump (seen in
  the first screenshots). First by a fixed height; with two more rows
  in Graphics, by `TabContainer.use_hidden_tabs_for_min_size`, which
  follows the rows.

## Anti-aliasing, added before the merge

After the first build the user asked for anti-aliasing options and how
they work. The game had none (Godot's default is off). Given the
rundown (MSAA, FXAA, SMAA, TAA, FSR 2), the user took my three
recommendations, again without further reasons: MSAA (Off/2×/4×/8×) and
a screen-space filter (Off/FXAA/SMAA) as two settings, MSAA 4× by
default, and built into C10 before it merges. Left out: TAA and FSR 2,
which blend frames and ghost on the waves, rain and clouds.

Godot 4.7.2's own class reference (raw XML, not a summary) says
screen-space AA is Forward+ and Mobile only, so under Compatibility it
is greyed out at Off, like the shadows; MSAA has no such note and works
there.

## Testing

`world_test.gd` → `_settings`. The world test now gives both `Settings`
and A05 its own settings file before the world is added, so it never
reads the developer's file (before, A05 read it at start). Headless
Godot can't capture the mouse, so the mouse-mode checks went to the live
check, as for the other menus. Screenshots of every tab under both
renderers (scratch script, not kept), and of Graphics again with the
anti-aliasing rows.

The docs check found that the bridges and performance tests, which load
the world through the layout demo, read the developer's own settings
file: a saved FPS cap or render scale could change what the
performance test measures. The demo now gives the world a fresh file
when a test runs it.
