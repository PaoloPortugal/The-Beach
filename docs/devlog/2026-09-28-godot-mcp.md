# Godot MCP plugin

Features: tooling

The user added the `addons/godot_mcp` editor plugin
([DaxianLee/godot-mcp](https://github.com/DaxianLee/godot-mcp), v1.0.0) so
Claude Code can drive the Godot editor. The plugin runs an HTTP MCP server
inside the editor at `http://127.0.0.1:3000/mcp`.

## Setup

- Registered in a project-scope `.mcp.json`. Local scope (`claude mcp add
  --scope local`) was the first suggestion, but the `claude` CLI isn't on
  PATH on the user's machine, and the user asked for everything to be tracked.
- Auto-start turned **off** (user's decision) by writing
  `godot_mcp_settings.json` in the project's Godot user-data folder. The
  plugin defaults to auto-start on, and only saves settings when changed in its
  dock, so the file was written directly.
- The upstream `LICENSE` was added next to the plugin; the copy in the repo
  didn't include it, and the licence requires it with every copy.

## Findings

- **Security:** the server has no auth and replies with
  `Access-Control-Allow-Origin: *` (`mcp_server.gd`), so any browser page can
  call its tools while it runs. File tools are limited to `res://` and
  `user://`. The user chose "auto-start off, run only when needed" over
  patching the CORS header, for now.
- **Licence:** custom non-commercial licence, not open source. Fine while the
  project is non-commercial.
