# C15: the hotbar

Features: C15, D01

While fishing's design was being written up (dev log
2026-10-27-d01-fishing-design), the user asked for an inventory first:
"just a simple hotbar you can switch items on with the mouse wheel or
the numbers on the keyboard", holding only the tools, the fishing rod
and the bug net. Then: the bug net later, the inventory now.

## Decided

The user's choices, all my recommendations except the fade:
- **Slot 1 is empty hands**, so the rod can be put away. Rejected:
  tools only, always holding one; tools only, with the held slot's
  number putting it away.
- **It shows when you switch and fades when idle** (the user's pick),
  over always shown at the bottom.
- **ID C15**, as in-world UI next to the crosshair (C11), over D02 or
  W13.

My picks for the details: number keys 1-9 bound (a number past the last
tool does nothing); wheel down for the next slot, round the ends; shown
for 1.5 s, then fading over 0.5 s; you start each game with empty hands
(not saved); nothing while you don't have the controls, as with the
crosshair.

## Built

`world/hotbar.gd` draws the row in code like the crosshair (a
placeholder, recorded in `assets/CREDITS.md`) and owns the input:
eleven new actions in `project.godot` (`hotbar_1` to `hotbar_9`,
`hotbar_next`, `hotbar_previous`). Before binding the wheel I checked
what else reads it: only the big map and the chat (each with the
controls off while open) and the live checklist, a dev tool, which
scrolled with the wheel while walking. It now scrolls with it only over
its panel with the pointer free (Page Up and Page Down from anywhere),
so the wheel is the hotbar's while walking, live checks included.

The world test's `_hotbar` sends real key and wheel events, so the
bindings are tested along with the logic. Holding the rod does nothing
yet; the rod in your hand and what it does come with D01.

Live check passed with the user (2026-10-27, Windows): "looks good".
