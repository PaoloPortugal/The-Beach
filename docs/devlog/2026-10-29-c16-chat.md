## My picks (said so in NOTES)

- The card's who line as nine whole sentences (three askers by three
  kinds), not "{who} asks to use {tool}:" with a translated "{who}":
  a language may need to inflect the asker or move the verb.
- A failed send or answer keeps its English and the sidecar's reason
  apart, filled when shown, so the line is said again in a new
  language without the reason being looked up as a key.
- Mode names under the context "permission mode", tool statuses under
  "tool status" ("ok", "running" alone are ambiguous).
- Plan choices for a mode with no wording of Claude Code's: "Yes, and
  switch to {mode} mode" with the mode's name as it reads alone. It used
  to lower-case it ("plan mode"); lower-casing translated text is
  wrong for some languages (German nouns), so it now reads "Plan mode".
  Only the plan mode itself has no wording of its own, and a plan is
  never approved into it in practice.
- The exact figures in the usage tooltip keep English's "," separator:
  left for the first real language (step 7).

## Found on the way

- Ids look like keys, so a `# TRANSLATE` line holding one beside our
  text (`"acceptEdits": "Accept edits"`) would have dropped neither
  and taken both. `PermissionModes` and `ToolFold.status_text` use
  `TranslationServer.translate` with literal strings instead.
- Several literals passed to helpers ("Yes", "No", "No, keep planning",
  the plan's line, the notes' placeholders) were missing from the
  template: they're auto-translated, but the extractor only takes a
  literal set to `text` or passed to `tr`. Now marked `# TRANSLATE`.
- A `tool.finished` event's `summary` is the call's result line, not a
  new summary: the test's expected rows say "Settings / Resume".
