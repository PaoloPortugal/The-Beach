# Diagrams restyled

Features: docs (docs/flows.md, docs/diagrams/, NOTES.md → Architecture)

## The request

The user asked for our diagrams to be made like the ones in their
software engineering course repo (2026-10-03): a «component» diagram
with colour-coded kinds and a legend, and sequence diagrams with
numbered steps, participants grouped in coloured boxes, a highlighted
band around the part that matters with a note naming its code, and a
status note on top of each.

Three choices went to the user:
- **Structure: split like their repo** (user's choice). One file per
  flow in `docs/diagrams/sequence/`; `docs/flows.md` became the index
  with the reading guide. The recommendation had been to keep one file,
  since "flow 9" references and the CLAUDE.md rule pointed at it. Those
  now point at the index, which still lists the flows by number.
- **A full component diagram in NOTES.md → Architecture** (user's
  choice), replacing the overview.
- **No PNG exports** (user's choice). GitHub draws Mermaid itself, PNGs
  go stale, and making them needs mermaid-cli and a headless Chrome.

## What changed

- **Sequence diagrams:** `autonumber`; a blue box "Ours" (World, Sidecar,
  Bridge, Relay) and a grey box "Claude Code, the user's own" (Claude
  Code, Transcript); one amber band per flow with a note naming the files
  that do that step (checked against the code: prompt pairing and
  subagent parents are in `hooks.ts`, held hooks and the stop reply in
  `session.ts`); a status line with the features and the NOTES section;
  a link back to the index. The steps and prose are unchanged, except
  that "flow N" in the prose is now a link.
- **Component diagram:** the course repo's colours (blue built, blue
  dashed planned, grey dashed external, green storage, orange actor),
  «component» / «external» labels, each box naming its folder or files,
  thick arrows across process boundaries labelled with transport and
  authentication, and a legend.

## Found along the way

- **Five flows didn't render on `main`** (0, 3, 9, 10, 11). A `;` in a
  sequence diagram's text ends the statement in Mermaid, so the rest of
  the line was a syntax error. GitHub would have shown an error box in
  place of those diagrams. Inside diagrams a semicolon is now written
  `#59;`. Every diagram was parsed and rendered with Mermaid 11 (light
  and dark themes) before handing over.
- **`mc` isn't a Mermaid theme.** The course repo's `theme: mc` is the
  Mermaid Chart editor's, which made their PNGs; GitHub ignores it. The
  look comes from explicit colours instead, see-through ones in sequence
  diagrams so they read in GitHub's light and dark themes.
- **A box label with brackets loses its colour**: `box rgba(...) Claude
  Code (the user's own)` showed the colour code as text. Hence the comma.
- **The first component layout sprawled**: Mermaid's layout handles
  arrows pointing back up badly. It reads top to bottom now, with fewer
  boxes (World and agents together, the relay as a label on the hooks
  arrow) and two-way arrows for request and reply links (hooks, bridge).
- The old icon for the actor (an embedded SVG stick figure) needs
  Mermaid 11.3's image shapes; not used, in case GitHub's Mermaid is
  older.
