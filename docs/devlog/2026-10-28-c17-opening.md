# C17: the game's opening

Features: C17 (with S01, C14)

Step 3 of branch `s01-start-retry` (the user's order, 2026-10-28): a
loading bar at the game's start. It became an opening. The design is
NOTES → C17 Opening.

## Decided (the user's, 2026-10-28)

- Where: a cover before the main menu, not a bar on the menu. My
  recommendation was the menu, keeping C14's "menu at once"; the user
  chose the cover.
- The user's idea: the developer's logo, then Godot's, "like a real
  game opening", using that time to cover the wait, with a bar if
  needed. Then, after giving me the logo and the name "moofys": maybe
  both on one screen, "looks less generic". I agreed and laid it out:
  the logo large in the middle, the name under it, "Made with" and
  Godot's logo smaller along the bottom.
- It waits for the sidecar's sync and, if sessions came back, the
  first island starting to rise, at most 5 s after the sync (my
  recommendation; rejected 2 s and every island up).
- My picks, taken ("your recommendations sound good"): the bar names
  the stage and fills a step per stage; a key or click skips the card;
  the card always shows its time; Godot's boot splash plain.

## How

- `Opening` (`world/opening.gd`) lies over the main menu, which still
  opens at start under it, so C14's code, camera and tests stay as
  they were; the opening fades out into it. Layer 9, under the quit
  dialog's 10, so closing the window during it still asks.
- Its stages read `SidecarClient.status` and a new `attempt()`; the
  island wait a new `SessionIslands.island_rising`, emitted as the rise
  starts (C14's islands rise once their ground is made).
- The logo: the user's PNG is 480×480 in 15-pixel blocks, a 32×32
  sprite; saved at 32×32 (upscaled again it matches the original
  exactly) and drawn with nearest filtering in whole steps, so its
  pixels stay square at any window size. Its black outline wants a
  light background, so the card is sand-coloured, and Godot's logo is
  the press kit's variant for light backgrounds.
- Godot's logo: downloaded from the press kit with the user's OK
  (CC BY 4.0, Andrea Calabró; credited in `assets/CREDITS.md`, which
  the main menu's Credits shows). The project's boot splash now shows
  no image, in the card's colour, so Godot's logo shows once and the
  start doesn't flash from dark to light.

## Found on the way

- A first cut used `_synced_at < 0` as "not synced"; the cap test,
  moving the sync back in time, tripped it. A separate flag now.
- D01's world_test checks failed in every run that afternoon,
  including on the branch's committed code without C17, so not the
  opening's doing. "The view turns with the rod's tip" read the view
  one physics frame after the mouse event, but the event arrives a
  frame later and the fight turns the view in `_process`, which runs
  after both `physics_frame` and `process_frame` (logged frame by
  frame: the rod moved in one step, the view in the same step's
  `_process`). So it read the rod moved and the view not yet. It now
  waits for the rod to move, then two process frames. "Reeling drags it
  through the water" missed once (0.24 m above against 0.15), and
  depends on where the throw lands and the waves.

## Tests

`tests/world/world_test.gd` → `_opening`: over the main menu at start,
the logo in whole pixel steps, keys waiting (an action isn't a skip),
the quit dialog over it with Esc reaching it, the fade into the menu
after its card's time; on stand-in clients the stages, the retry text,
the wait for the first island and its 5 s cap, a failure, the
`TIMEOUT_S` bound, none for a sidecar already failed. The quit dialog
and the timeout checks came from the security review, which found no
must-fix; it also flagged the logo's licence in an MIT repo (the
user's call, in docs/release.md) and Godot's logo needing its credit
in exports (release.md too). The look, the fades and
skipping by key or click are the live check's.
