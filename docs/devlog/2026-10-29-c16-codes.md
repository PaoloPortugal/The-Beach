# C16: codes for the sidecar's messages

Features: C16, Protocol, S02, S06, S08, C05, C10, S03, S04

Step 6 of C16's migration order (NOTES → C16 → How the codes work). The
sidecar stays English and is sent no locale; what it tells the player
now carries a code Godot words and translates, so the refusals, the
program not found, the sign-in notice and the permission options in the
terminal's words can follow the game's language. No real language ships
yet. In English almost nothing changes on screen.

## Decided (user's, 2026-10-29: "option A")

1. **Optional `reason` + `details` on error replies, on a not-found
   `program` and on notices; optional `kind` + `parts` on permission
   options.** Details are string values, parts a string or a list of
   strings. Godot words the reasons and kinds it knows, translated, and
   shows the sidecar's English `message` or `label` for any other.
   Additive, no protocol version change. No locale goes to the sidecar,
   as decided with C16's design (2026-10-27).
2. **Godot's text uses `{provider}` (hello's name) and `{program}`
   (`capabilities.program_path.program`)**, so no provider's name is in
   Godot's text; the details and parts are content, filled in one pass.
3. **Scope: core.** Reasons and kinds are generic names; a provider
   sends the ones it has.

## My picks (said so in NOTES)

- One class, `SidecarText` (`core/sidecar/sidecar_text.gd`), for every
  place that shows the sidecar's words, instead of each caller wording
  its own.
- A text whose placeholder has no value falls back to the sidecar's
  English whole, rather than showing a hole or "{path}".
- An error without a reason is worded by its code where that has one
  meaning (`unknown_session`, `session_starting`).
- Godot's own `disconnected` replies carry `not_running` and `dropped`,
  so they're worded the same way.
- `set_path_broken` carries its `why` (another program reason) and that
  reason's details, so the outer sentence and the inner one are both
  ours.
- Commands beside folders (`allow_folders_and_commands`) are JSON-quoted
  by Godot, as the sidecar's label does, so the English reads the same.
- The invalid project reasons and `end_in_terminal` are worded as whole
  sentences ("The project's folder doesn't exist."): the sidecar's
  English there is a lowercase developer message.
- The launcher's `_say` takes Callables, so a refusal worded from a
  reason is worded again when the language changes.
- The `outside_sessions_off` line in the settings is ours now
  (translated), no longer content.
- The unit test lives in the locale suite (`_sidecar_text`), so the CI
  list didn't change.

## Found on the way

- Running a suite right after adding a `class_name` file fails to parse
  every caller ("Identifier not declared") until Godot's class cache is
  refreshed: `godot --headless --path . --import` once.
- The world test's missing-folder check read the sidecar's English
  ("does not exist"); it now reads ours.
