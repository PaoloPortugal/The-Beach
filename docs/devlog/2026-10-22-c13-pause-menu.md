# C13: the pause menu

Features: C13, C10, S05, W03, A05, C01

The user had been quitting with Alt+F4 and asked for a general pause menu
on Esc with "Quit game" and "Settings" (2026-10-22). Designed as four
choices with a recommendation each. The user took three: its own ID,
C13, rather than folding it into C10; nothing pauses (sessions are live,
so only the controls and the mouse are released, as the settings menu
did); Esc in Settings goes back to the pause menu. For the look they
went further than my two-button panel: a **Resume** button as well, and
the screen dimmed behind the panel. NOTES.md → C13 has the decisions
and the rejected options.

## What was built, and my picks

- `PauseMenu` (`world/pause_menu.gd`), made by `world.gd`. It takes Esc
  the way C10's menu did: opens in `_unhandled_input`, so the chat, the
  sessions menu, the map and the debug console still close first; closes
  in `_input`. The settings menu no longer opens on Esc.
- Esc back from the settings: a `back` callable on `SettingsMenu`, set by
  the pause menu, called instead of giving the controls back, so the
  mouse isn't captured and freed again in one frame. Unset, Esc closes
  the settings as before. Its hint now reads "Esc to go back".
- The dim is a `ColorRect` in the pause menu's layer (2, the settings
  menu's). The world adds the pause menu just before the settings menu,
  so on the same layer the dim is drawn under the settings panel too and
  stays while Settings is open. The usage limits (layer 4) stay above
  it.
- "Quit game" goes through `QuitGuard.request_quit` (S05), the same path
  as closing the window. Its "Back to the game" leaves the pause menu
  open: the guard gives back the controls as they were, which is off.
- Buttons take no keyboard focus, like the settings menu's controls.
