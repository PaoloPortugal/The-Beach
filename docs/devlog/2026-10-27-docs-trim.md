# Trimming NOTES.md and the last spike

Features: docs

Asked by the user (2026-10-27), after asking whether the codebase had
grown too much: the code had grown about as expected for the features
built, but NOTES.md (about 7,700 lines, read every session) carried a
lot it doesn't need every time. Three steps, the user's pick of four:

- **The Markdown spike deleted** (`spikes/markdown/`, about 1,500
  lines): NOTES' own rule deletes a spike once its feature is built, and
  C03 is. Its 74 checks and sample files already live in `tests/chat/`;
  the code is in git history.
- **The merge log moved** from NOTES → Known issues and next steps to
  its own dev-log entry (2026-10-27-merge-log), with the M1 review, the
  v1 handoff and the two S02 checkpoints beside it: about 375 lines of
  history. Git's merge commits already record later merges.
- **Release plans moved** from NOTES → Watch items to
  `docs/release.md` (Anthropic's terms, Claude branding, code signing,
  Steam, itch.io, export presets, `icon.svg`, before the repo goes
  public): about 120 lines. NOTES and CLAUDE.md list the new doc; every
  reference (NOTES, two sidecar comments) points there now.

NOTES.md went from about 7,690 to 7,200 lines. Not done as a project
(the user's, after hearing it'd take most of a day for a small gain):
rewriting each System section to its current design. Instead, the
"When a feature lands" checklist (and the land skill) now fold a
section's "Changed …" history into the current text whenever a branch
touches it, moving the story to the dev log.
