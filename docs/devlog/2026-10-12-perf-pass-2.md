# The second performance pass: the Mobile renderer (WIP)

Features: Architecture → Performance, Architecture → Rendering, C10

WORK IN PROGRESS on `perf-pass2`: measured, the renderer decided and
switched in `project.godot`; tests, docs and the live check still to do.

The user asked for another optimization pass after C10's live check:
their machine (integrated AMD Radeon) couldn't run MSAA fast enough
under Forward+.

## Measuring (2026-10-12)

The layout demo (64 sessions) at 1920x1080, vsync off, noon, clear,
`seed(1234)` so every run builds the same islands; GPU time per frame,
median of 180 frames, at four views: the platform looking out and back,
an island (`arrival_point("d01")`), a bridge's middle above its deck
looking along it. Runs vary by 1-3 ms. (The first rounds' bridge view
was under the water, inside the bridge's box with its posts; fixed.)

Forward+, saving per frame by hiding or changing one thing:
- MSAA 2x +5-8 ms, 4x +10-15 ms; FXAA +1.5-2 ms, SMAA +3.5-4 ms.
- Sun shadows off -4 to -9 ms; Low shadows -2 to -5 ms; hard shadow
  filtering, a 60 m shadow distance: within the spread.
- Render scale 75 %: about a third less. Fill-bound, not triangles.
- The ocean -3 to -7 ms; the island ground -4 to -12 ms (the bridge
  view, where cliffs overlap); props, clouds, the seabed, bridges, the
  agents: about 1 ms or less each. Night (lamps, torches): +0-3 ms.
- Per-vertex shading on the islands' 1,143 materials: no gain, slower
  on the island view.
- **Depth pre-pass back on** (Watch items): -3 to -17 ms, but the black
  striped triangles are still there in 4.7.2, the latest release. Not
  an option.

**Mobile renderer**, the same scenes (ms, Forward+ → Mobile → Mobile
with MSAA 2x): platform out 18.5 → 10.1 → 14.4; back 21.1 → 12.7 →
15.9; island 15.6 → 10.3 → 14.3; bridge 31.5 → 16.0 → 21.3. Day,
night and storm screenshots look the same, apart from a slight
banding in Mobile's night sky (about 3 levels near the top, a faint
purple arc), still there with `use_debanding` on.

## Decision (user's, 2026-10-12)

**Switch to the Mobile renderer** (my recommendation; rejected: a
Forward+/Mobile choice in the settings, which needs a restart and
reverses C10's "no renderer setting"; staying on Forward+, where nothing
smaller measured beyond the spread). The Compatibility fallback stays.
Given up: SSAO, SSR, SDFGI and volumetric fog (none used), 8 lights per
mesh at most. `project.godot`: `renderer/rendering_method="mobile"`,
`anti_aliasing/quality/use_debanding=true` (its cost was within the
spread).
