# C14: the main menu

Features: C14, C13, S07, W01, W04

## Where it came from

The user asked for a main menu (2026-10-26). Its shape was settled
before any code, in two rounds (NOTES C14 → Decided): over the live
world in place of S07's loading cover, a camera circling the islands
that eases down to the player on Play, Play / Settings / Credits /
Quit, and "Main menu" in the pause menu. Then, before building: the
pause menu's centred panel (not my left column), the working name as
the title (listed for the rename), Play never held back for the
sidecar (not my "wait for the sync"), and Credits as CREDITS.md itself
plus Godot's own notices.

During the build:
- The loading cover had no job left. I recommended deleting it; the
  user kept it, unused. Its tests on stand-in sidecars stay; the part
  that checked it over the world became the menu's start test.
- The user asked for "a back to main menu button in addition to the
  regular quit" in the pause menu: it was already planned (C14 →
  Decided) and went in as **Main menu** between Settings and Quit game.

## What was built

- `world/main_menu.gd` (`MainMenu`): the panel, its dim, the credits
  page, and the HUD it hides. Settings borrows `SettingsMenu.back` and
  puts the pause menu's back when Esc returns.
- `world/menu_camera.gd` (`MenuCamera`): orbit, ascend, descend. The
  circle is the middle of the platform and every island, 40 m past the
  farthest, clamped to 60-220 m so it stays inside the fog (ends at
  390 m) and the islands' draw distance. The eases blend the whole
  transform (`interpolate_with`) and the field of view with a
  smoothstep, aiming at the player's camera as it is each frame.
- `world/pause_menu.gd`: the button and `main_menu_chosen`.
- `world/world.gd`: makes both, opens the menu at the end of `_ready`
  where the cover was added, adds `main_menu.is_open()` to the
  minimap's `hidden_when`.
- `MainMenu.close_now()` for the layout and ring demos, which want the
  world at once; the bridges suite runs the layout demo, so without it
  the minimap checks there would have seen the menu.

Godot's notices, behind a toggle: after seeing the page, the user was
surprised by the long list (FreeType, ENet, mbedTLS and dozens more)
and asked whether it was inspiration I'd been noting. It's Godot's own
list of what is compiled into every Godot game. The user's call: keep
it on the same Credits page behind a **Show Godot licences** toggle,
and CREDITS.md does for now, though a player-facing credits file will
likely be needed. `Engine.get_license_text()` is Godot's own MIT text;
`get_copyright_info()` lists the third-party parts (FreeType, ENet,
mbedTLS and the rest) with their copyright lines, and
`get_license_info()` the licences' texts. All of it is shown, as plain
text (never read as BBCode), so a shipped build carries every notice
Godot asks for. It's built the first time the toggle shows it.

Links in the credits open straight in the browser: the file is ours,
not session content, so the chat's "ask before opening" (Security
rules) isn't needed. Only http(s) and mailto links are clickable
anyway (the Markdown parser).

## The live check, and what it found

All 15 steps passed (the user, real Claude). The user's notes:

- **The menu stuttered as islands from before came in.** The loading
  cover used to hide this. Timed headless: making an island's ground
  (`IslandGenerator.build`) takes 55 ms (beach) to 90 ms (mountain),
  all on the main thread, and the sync places every taken-back island
  in one frame. A new island mid-game hitched the same way, unnoticed.
  The fix (user's pick of two): the ground is made on a
  `WorkerThreadPool` task. `build` split into `make` (pure: the grid,
  top, mesh arrays and faces, changing nothing on the generator) and
  `take`; the task runs on a generator of its own and writes only to a
  dictionary it shares with the island, so freeing the island
  meanwhile is safe (it waits for the task on predelete). The mesh is
  made from the arrays on the main thread (`commit_to_arrays` then
  `add_surface_from_arrays`, the same as `commit`). Rejected: one
  island a frame, which only splits a 300 ms stall into 90 ms ones.
- **Islands popped up instead of rising.** S07 had chosen that on
  purpose ("standing from the first frame", under its cover). The user
  wants them rising behind the menu now, with no beacon. Every island
  now waits out of sight (`BUILDING_Y`) until it's built, then rises
  from `sunk_y`; `top` (for `sunk_y`) is only known once built, which is
  why it doesn't start from `sunk_y` straight away.
- **Play put the player back on an island whose session had ended
  behind the menu, and only then did it sink.** The empty island waits
  for the player to leave (W04), and on the menu they hadn't. The user's
  call: it sinks at once and Play goes to the platform. `player_away`
  on `SessionIslands`, set from the menu's new `opened` / `leaving`
  signals; a flag says whether an island sank from under the player,
  and `leaving` sends them to the platform before the camera eases
  down, so the ease ends there.

Tests: the world test had assumed a taken-back island was standing the
moment its snapshot came; `_islands_up` waits for every island to be
built and up. New checks: the island out of sight while built, then
rising; the sink behind the menu and Play to the platform, once only.
A lambda holding the freed island failed the first run ("Lambda
capture was freed"); a weakref, as elsewhere in the test. The layout
demo's islands rise too now, so the bridges and performance tests wait
for `SessionIslands.all_up` before checking them, and the performance
test finds an island's ground mesh by type (the orchestrator now comes
first among its children).

The re-check (8 steps) passed with the user. It's still not quite as
smooth as they'd like as islands come in, which they put down to their
hardware. Not measured: what's left on the main thread once an island
is made (the collision shape, its props' MultiMeshes, uploading the
mesh), a few ms an island by the headless timings.

## Not done

- A player-facing credits file (user's, likely later); CREDITS.md is
  shown as it is until then.
- No export presets exist yet. When they do, `assets/CREDITS.md` must
  be in the export's include filter (non-resource files aren't
  exported by default), or Credits says the file couldn't be read.
- The look is a placeholder, like all UI.
